## Label-blind audit (done before this protocol; no preferred-response or feedback column read)
CA first turns: 62,295 conversations use pre-generated prompts; **2,928 identical items** (same prompt text and the same four response texts) are shown to ≥ 2 users, covering 49,616 conversations; median 15 users per item (10th–90th percentile 9–31); one language per item; the four responses appear in one order for 99.97 % of items; 2,877 users, median 19 shared events each (top 10 % of users contribute 21 %).

## S13-1 (primary): who chooses what on identical items — CA first turns
**Items.** An item = exact (prompt, ordered four-response) identity; items with more than one presentation order are dropped. No near-duplicate or embedding matching.
**Design.** Stage-8/12 user folds and prompt-group folds (prompt group = prompt text, so every item lies in one prompt-group fold) and the `sap_ca.py` per-fold population model (base + per-language μ, fitted on training users × training prompt groups only; no fitted prediction or prior uses a test item). Learners, both frozen from Stage 12 unchanged: **validated isotropic adaptation (primary)** and TRV (secondary), each with attribute set and strength selected on the fold's pseudo-new training users. Test users = test-fold users with ≥ 20 support events in training prompt groups; 5 support draws (seeds 10,000 f + d); test events = their events on identical items in held-out prompt groups.
**Feasibility gate (label-blind, checked before outcomes):** ≥ 300 items with ≥ 2 test users of the same fold; otherwise S13-1 is declared infeasible and not relaxed.
**Endpoint A — identity on identical items.** For every item and every pair (u, v) of its test users from the same fold who chose different responses a ≠ b, S = (δ_u − δ_v)ᵀ(x_a − x_b), δ = adapted minus population attribute weights, x = the response's attribute vector (the population terms cancel exactly); assignment log-score gain = log σ(S) − log ½ (nats), averaged over the 5 draws, then averaged within item, then over items (equal item weight); assignment accuracy 1[S > 0] (½ at S = 0) likewise. Pairs who chose the same response do not enter (they carry no assignment information). Inference: two-way bootstrap with independent multinomial weights for items and users (a pair's weight = item weight × weight_u × weight_v; B = 1,000, seed 17), which accounts for users appearing in several items and as both members of pairs.
**Endpoint B — benefit on the same panel.** All test events on identical items (agreements included): own − μ pairwise winner-versus-other accuracy and log-likelihood per pair; user bootstrap (seed 17, 2,000; primary, as Stage 12) and user × item two-way (secondary).
**Decisions (paper wording fixed now).** (1) Endpoint A log-score lower bound > 0: "support histories predict differences between users choosing among identical displayed alternatives". (2) (1) and both endpoint-B lower bounds > 0: "those differences support beneficial personalisation on the shared-item panel". (3) (1) without (2): "individual differences are predictable, but exploiting them has not established a choice benefit". (4) Endpoint-B accuracy upper bound < +1: procedure-specific sub-threshold statement. (5) Endpoint A interval covering 0: no identification claim (not evidence of absence). Even (1) identifies persistent user-specific choice predictability, not an intrinsic "length preference". TRV − isotropic reported for both endpoints; advantage only if its lower bound > 0.

## S13-2 (supporting): frozen procedure on MultiPref
Native preference direction, ties excluded, binary; one comparison = one event; Stage-1 rater folds and prompt-group folds (seed 0) and validation flag; population model = ridge on the existing MultiPref text features + μ (one language), refitted on training folds only; the 24 `attr_feats.py` attributes; the same isotropic (primary) and TRV (secondary) selection on pseudo-new training raters (20 %, seeds 3 + f / 40 + f), k = 20 support events from training prompt groups, 5 draws; test on held-out prompt groups. **Gate:** ≥ 100 eligible test raters over folds, else not run. Decisions: both lower bounds (accuracy, LL; rater bootstrap primary, rater × prompt-group two-way secondary) > 0 → "the frozen procedure benefits held-out raters in a second dataset"; accuracy upper bound < +1 → bounded small gain there; otherwise inconclusive (or harm if the upper bound < 0); TRV − isotropic as in S13-1. PRISM is not run.

## S13-3 (conditional): do first-turn user deviations transport to third turns?
**Gate (before any third-turn label is read):** count third-turn choices of S13-1-style eligible users (≥ 20 first-turn support events) and the history-including texts to embed; run only if ≥ 500 users have ≥ 5 third-turn choice events and embedding fits in one GPU day (≤ ~1.2 M texts at the measured rate, history serialised as the chat transcript truncated to the last 6,000 characters). Otherwise skipped and stated as a limitation. Turn 4 is not opened.
**Design.** Freeze each user's first-turn isotropic deviation δ̂_u^(1) (Stage-12 selection on first turns, 20 support events, draw 0) in first-turn attribute units. Third-turn population model m₃ (ridge on history-conditioned Qwen2.5-7B features of (conversation through turn 3 prompt, response) + per-language μ₃) fitted on other users' third turns; compare m₃ with m₃ + a₃ᵀ δ̂_u^(1) on the user's third turns of conversations not used for support; no rescaling, selection or tuning of the transported deviations. Endpoints and decisions: both lower bounds > 0 → "first-turn user deviations improve prediction in later, disjoint conversations beyond a history-conditioned population model"; otherwise "coefficient transport unsupported for this procedure and panel" (not "preferences are unstable").

**Amendment 2 (2026-11-04 10:46, after the S13-1 result, before running; robustness to position).** The sixth review named position sensitivity as an alternative explanation, and a label-blind check (1,500 identical items) shows that the four fixed positions differ systematically in the primary attributes (within-item deviation of positions a…d: length −0.055 / −0.007 / +0.037 / +0.026, paragraphs −0.056 / −0.035 / −0.021 / +0.112, list −0.059 / −0.069 / −0.032 / +0.159; s.e. ≤ 0.013), so a user's position habit could appear as an attribute deviation. Robustness run (`S13POS=1 s13_1.py`, everything else as S13-1): three position-difference columns (one-hot of positions b, c, d of response B minus that of response A) are appended to the attribute differences, so the per-language population model also has position effects; the isotropic learner adapts the attribute set **jointly with the position columns** (sets {length + pos; prim3 + pos}, τ² by the same pseudo-new-user validation); a **position-only** learner (pos, τ² validated) is run beside it. Endpoint A is computed from the joint model's attribute part only (S_attr = (δ_u − δ_v)ᵀ(x_a − x_b) over the attribute columns), its position part only, and the position-only learner. Reading (fixed now): if S_attr's log-score lower bound stays > 0, the identical-item identity is **not explained by user position preferences**; otherwise the S13-1 identity statement is restated as "user-specific choice predictability that may reflect position habits". Endpoint B reported for the joint and position-only learners. TRV is not run in this robustness pass.
